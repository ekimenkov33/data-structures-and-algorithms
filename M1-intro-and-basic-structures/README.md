# Отчёт по лабораторной работе № 1

**Тема:** Анализ временной сложности элементарных алгоритмов

**Дисциплина:** Структуры и алгоритмы обработки данных

---

### 1. Цель работы

Научиться определять временную сложность алгоритмов аналитически (асимптотические оценки для худшего случая) и подтверждать полученные оценки экспериментально с помощью эмпирического профилирования (бенчмаркинга) по методологии воспроизводимости.

---

### 2. Ход выполнения работы и реализация алгоритмов

В рамках лабораторной работы были реализованы четыре элементарных алгоритма без использования встроенных функций `sum`, `max` и штатного оператора возведения в степень:

1. **Сумма элементов массива** (`calc_sum` / `array_sum`): линейный обход элементов с накоплением суммы.


2. **Поиск максимума** (`find_max` / `array_max`): поиск наибольшего элемента в непустом массиве путем последовательного сравнения.


3. **Подсчет пар равных элементов** (`count_equal_pairs`): двойной цикл для перебора всех уникальных пар индексированных элементов $(i, j)$ при $i < j$.


4. **Бинарное возведение в степень** (`binary_pow_mod`): алгоритм быстрого возведения в степень методом деления показателя пополам (квадрирования) с поддержкой вычислений по модулю.



---

### 3. Аналитическая оценка (Худший случай)

| Алгоритм | Аналитическая оценка | Обоснование |
| --- | --- | --- |
| **Сумма элементов** | $\Theta(n)$ | Выполняется ровно один проход по массиву длиной $n$, на каждой итерации задействована элементарная операция сложения.

 |
| **Поиск максимума** | $\Theta(n)$ | Осуществляется $n-1$ сравнений элементов при линейном сканировании массива.

 |
| **Подсчет пар** | $\Theta(n^2)$ | Внутренний цикл выполняется убывающее число раз: $(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2} = \Theta(n^2)[cite: 4]$. |
| **Бинарное возведение в степень** | $O(\log_2(\text{exp}))$ | На каждой итерации цикла показатель степени $\text{exp}$ целочисленно делим пополам ($\text{exp} = \text{exp} // 2$), что приводит к логарифмическому числу шагов.

 |

### 4. Верификация кода и инварианты

Перед проведением замеров программный код прошел верификацию по методике `docs/ai-verification.md`:

* **Репрезентативные тесты:** Проверены граничные случаи (пустой массив, массив из одного элемента, массив из одинаковых элементов, нулевая степень).


* **Инварианты:** Для подсчета пар зафиксирован инвариант — на массиве из попарно различных элементов функция возвращает `0`, а на массиве из трех одинаковых элементов — ровно `3` пары.
* **Сверка с эталонами:** Результаты работы разработанных функций на случайных наборах данных полностью совпали с эталонными встроенными функциями Python (`sum`, `max`, `pow`).



---

### 5. Эмпирические замеры и результаты бенчмаркинга

Замеры времени выполнялись на данных варианта № 18 (сгенерированных детерминированно с использованием seed = $30 + 18 = 48$) по методологии бенчмаркинга (предварительный прогрев интерпретатора, выполнение не менее 5 повторов для каждого размера входа с последующим взятием медианы).

* **Линейные алгоритмы (`array_sum`, `array_max`)**: при увеличении размера входного массива в 10 раз (с $10^3$ до $10^4$) время выполнения возрастает приблизительно в 10 раз, что строго соответствует теоретической оценке $\Theta(n)[cite: 4]$.
* **Квадратичный алгоритм (`count_equal_pairs`)**: при увеличении размера входа с $10^3$ до $10^4$ время выполнения возрастает примерно в 100 раз, подтверждая сложность $\Theta(n^2)[cite: 4]$.
* **Логарифмический алгоритм (`binary_pow`)**: замеры проводились с вычислением по модулю (`POW_MOD = 1_000_000_007`). Использование модуля принципиально важно: оно предотвращает переход Python на тяжелую «длинную арифметику» при больших степенях, позволяя замерять именно число итераций алгоритма, а не рост разрядности чисел в памяти. Построение `log-log` графика для логарифмических зависимостей неинформативно (график вырождается в нелинейную кривую, по которой трудно судить о порядке роста), поэтому для него используется линейная шкала по оси $\log_2 n$.
